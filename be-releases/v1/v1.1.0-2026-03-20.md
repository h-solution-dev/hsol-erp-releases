## <span id="콘텐츠-채널-api-응답-확장">콘텐츠 채널 API 응답 확장</span>

**설명**  
`GET /api/v1/content-channels` 응답의 각 병원 객체에 `keywordsMemo`(병원 `memo.keywords_memo`), `assignedMembers`(departmentId 쿼리 시 해당 부서 담당자만)를 추가했습니다. memberIds가 2명 이상일 때는 N+1을 제거하고, 병원 ID 배치 조회 후 채널 1회 조회·메모리 분할로 성능을 개선했습니다.

---

## <span id="콘텐츠-채널-매퍼-구조-정리">콘텐츠 채널 매퍼 구조 정리</span>

**설명**  
병원별 채널·메모 조합 등 변환 로직을 서비스에서 ContentChannelMapper로 이전했습니다. `toHospitalsWithChannelsAndMemo`, `toHospitalsWithChannelsAndExternalMemo` 등 static 메서드로 두어 CA/DDD 스킬의 매퍼 역할에 맞춰 두었습니다.

---

## <span id="병원-keywords_memo-api-및-hospitalmemomapper">병원 keywords_memo API 및 HospitalMemoMapper</span>

**설명**  
병원 `memo.keywords_memo` 전용 수정 API `PATCH /api/v1/hospitals/:id/keywords-memo`를 추가했습니다. Hospital[]에서 memo 필드만 Map으로 뽑는 변환은 hospitals 모듈의 HospitalMemoMapper(`toKeywordsMemoByHospitalId`, `toExternalKeywordsMemoByHospitalId`)로 두어, content-channels 서비스는 해당 매퍼만 사용하도록 정리했습니다.

## v1.1.0 상세

### <span id="외주-메모-api">외주 메모 API</span>

**설명**  
병원 `memo.external_keywords_memo`(외주 작가 메모) 전용 수정 API를 추가했습니다. `UpdateExternalKeywordsMemoDto` 및 hospitals 서비스·컨트롤러 확장, content-channels 연동 정리 포함.

---

### <span id="키워드-기획-주제-null-허용">키워드 기획 주제 null 허용</span>

**설명**  
content-plan-item의 기획 주제(planningSubject 등) 필드를 null 허용으로 변경했습니다. 엔티티·DTO·리포지토리·서비스 전반 반영.

---

### <span id="키워드-메모-기능">키워드 메모 기능</span>

**설명**  
키워드 메모 저장·조회 및 병원 `keywords_memo` PATCH API를 확장했습니다. content-channels API 수정, `UpdateKeywordsMemoDto` 추가, hospitals 서비스·컨트롤러 및 users 리포지토리(HospitalUser 등) 보강.

---

### <span id="채널메모-매퍼-정리">채널·메모 매퍼 정리</span>

**설명**  
ContentChannelMapper·HospitalMemoMapper 등 채널·병원 메모 변환 로직을 정리·보강했습니다. content-channels 서비스에서 매퍼로 책임 이전, HospitalPackageInfo 매퍼 조정 포함.

---

### <span id="키워드-발행-publishdate">키워드 발행 publishDate</span>

**설명**  
키워드(콘텐츠 플랜 아이템) 발행 시 발행일(publishDate)을 지정할 수 있도록 했습니다. create-content-plan-item DTO·서비스·리포지토리 수정.

---

### <span id="패키지패키지-아이템-타입-리팩터">패키지·패키지 아이템 타입 리팩터</span>

**설명**  
패키지(packages) 모듈을 CQRS/DDD 구조로 리팩터했습니다. 패키지 CRUD API, package-item-types 모듈(아이템 타입 CRUD·CQRS 핸들러) 신규 구성, 도메인 엔티티·리포지토리·인프라 분리. 기존 레거시 packages 서비스·리포지토리·엔티티 제거 및 새 presentation·application·infrastructure 레이어로 전환.

---

### <span id="자동화-로그-automation_kind-추가">자동화 로그 automation_kind 추가</span>

**설명**  
`platform_automation_logs`에 `automation_kind` 컬럼을 추가했습니다. 자동화 시나리오를 구분하기 위해 `KARROT_NAVER_BLOG_UPLOAD`, `KEYWORD_PLAN_BLOG_VISIT` ENUM을 정의했고, 당근 업로드 로깅 시 `automationKind: KARROT_NAVER_BLOG_UPLOAD`가 저장되도록 반영했습니다.

---

### <span id="패키지-항목-분리-sql-보강">패키지 항목 분리 SQL 보강</span>

**설명**  
패키지 항목 분리 마이그레이션 SQL을 보강했습니다. `package_item_types`·`package_item_values` 기반의 quantity/string/enum 매핑, `hospital_package_items`의 코드/ID 매핑 이관, 세미콜론 누락·부분 실행 상태를 고려한 안전 롤백 시나리오를 정리했습니다.
