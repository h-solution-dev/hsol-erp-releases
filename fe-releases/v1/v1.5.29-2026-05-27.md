## <span id="root-권한-도입">📋 root 권한 도입</span>

### 설명

최상위 관리자 권한 `root` role을 새로 도입했습니다. `root`는 기존 `admin`이 수행할 수 있는 모든 작업(관리자 페이지, 게시글/댓글 관리, VPN 슬롯 관리, 콘텐츠 계획 삭제, 당근 업로드 이력 삭제 등)을 동일하게 수행할 수 있습니다. 흩어져 있던 `role === 'admin'` 체크는 `hasAdminAccess(user)` 헬퍼로 일원화되어, 향후 권한 정책 변경 시 한 곳만 수정하면 됩니다. `ROLE_LABELS`에서는 admin과 root 모두 "관리자"로 표시됩니다.

### 사용 방법

1. 백엔드에서 사용자 `role` 값을 `root`로 설정
2. 해당 계정으로 로그인하면 admin이 접근 가능한 모든 UI/기능이 동일하게 노출됨
3. 관리자 페이지 사원 탭에서 role 라벨은 "관리자"로 표시됨

### 예제

admin 전용이던 `/admin` 페이지, 헤더의 관리자 버튼, 모든 게시글/댓글 수정·삭제, VPN 슬롯 생성·수정·삭제, 콘텐츠 계획 아이템 삭제 등 모든 관리자 권한이 root에게도 자동으로 적용됩니다.

## <span id="당근-업로드-이력-삭제">📋 당근 업로드 이력 삭제</span>

### 설명

당근 업로드 이력을 삭제할 수 있는 기능이 추가되었습니다. 삭제 시 `karrot_upload_details` 행이 soft delete 되며, 5초 내에 같은 병원/URL의 발행 보고서(`pub_karrot_posts`) 행도 자동으로 제거됩니다. 같은 블로그 포스트로 재업로드도 다시 가능해집니다. 삭제 버튼은 admin/root에게만 노출되며, `/automation/karrot-upload-details` 요약 페이지와 병원 상세의 당근 자동화 탭 양쪽에서 동일하게 사용할 수 있습니다.

### 사용 방법

1. 당근 업로드 요약 페이지 또는 병원 상세 → 당근 자동화 탭으로 이동
2. 삭제하고 싶은 업로드 이력 행의 "삭제" 버튼 클릭
3. 확인 다이얼로그에서 게시글 제목 확인 후 "삭제" 클릭
4. 삭제 완료 토스트가 표시되고 통계/목록이 자동 갱신

### 예제

"삭제 → [게시글 제목]을(를) 삭제하시겠습니까? 이 작업은 되돌릴 수 없으며 발행 보고서에서도 제거됩니다." 다이얼로그에서 확정하면, 통계 카드(완료/실패/미시작)와 테이블이 즉시 갱신되고 같은 블로그 포스트로 재업로드가 가능해집니다.

## <span id="당근-버튼-노출-정책-완화">📋 당근 버튼 노출 정책 완화</span>

### 설명

네이버 블로그 페이지 테이블 각 행의 "진료일정 당근", "건강정보 당근" 업로드 버튼이 admin 전용이었으나, 전체 사용자에게 노출되도록 변경되었습니다. 게시글 타입이 `진료일정` 또는 `건강정보`인 경우에만 표시되는 조건은 유지됩니다.

### 사용 방법

1. `/automation/naver-blog` 페이지로 이동
2. 게시글 타입이 진료일정/건강정보인 행의 "당근" 버튼 클릭
3. 확인 다이얼로그에서 업로드 진행

### 예제

이전에는 admin 또는 root만 당근 업로드 버튼을 볼 수 있었으나, 이번 릴리스부터는 일반 user를 포함한 모든 권한에서 진료일정/건강정보 타입 게시글에 한해 당근 업로드를 실행할 수 있습니다.

## <span id="컨펌-에디터-tiptap">📋 컨펌 에디터 (Tiptap)</span>

### 설명

채널 발행 원고를 작성·검토할 수 있는 리치텍스트 에디터를 도입했습니다(Tiptap 기반). 토큰 인증으로 보호되며, A4 페이지네이션·이미지 S3 업로드·채널별 템플릿 자동 프리필을 지원합니다. v1.5.6에서 최초 구현 후 v1.5.7(페이지네이션·저장 UX), v1.5.8(null 방어), v1.5.12(S3), v1.5.14(템플릿 프리필)에 걸쳐 보강되었습니다.

### 사용 방법

1. 채널 발행 보고서에서 행의 원고 보기/편집 진입
2. 컨펌 에디터가 새 창으로 열림 (토큰 인증)
3. 신규 작성 시 채널 타입에 맞는 템플릿이 자동 입력됨
4. 이미지 삽입 시 S3에 자동 업로드되며 URL이 본문에 삽입됨
5. A4 페이지 단위로 표시되며 저장 버튼으로 보존

### 예제

지식인/네이버 블로그/스레드/카카오 등 채널별로 미리 정의된 템플릿이 자동 입력되어 작성자가 매번 처음부터 쓰지 않아도 됩니다. 이미지를 드래그해 넣으면 S3에 업로드 후 URL이 본문에 반영되어, 별도 호스팅 작업 없이 컨펌 진행이 가능합니다.

## <span id="채널-타입-확장">📋 채널 타입 확장 (thread / 구글블 / 카카오)</span>

### 설명

발행 채널을 점진적으로 확장했습니다. v1.5.5에서 인스타그램 thread(스레드) 채널을 추가하고, v1.5.17에서 블로그 타입에 구글블을 더했으며, v1.5.20에서 카카오 채널과 인스타 카드뉴스/릴스 통합 수량 분배를 도입했습니다. 키워드 캡처 이미지(v1.5.28)에도 thread 채널 표기가 반영되었습니다.

### 사용 방법

1. 채널 발행 페이지에서 새 채널(스레드/구글블/카카오) 선택
2. 인스타그램 채널은 카드뉴스/릴스를 통합 수량으로 입력 → 자동 분배
3. 키워드 기획 캡처 이미지에서도 동일한 채널 배지가 표시됨

### 예제

기존 인스타그램 카드뉴스 5건 + 릴스 3건처럼 따로 입력하던 것을 통합 수량 8건으로 입력하면 자동 분배됩니다. 스레드/구글블/카카오 채널은 채널 발행 보고서·키워드 기획 캡처에서 별도 배지로 식별됩니다.

## <span id="클릭-복사-통합">📋 클릭 복사 통합</span>

### 설명

테이블의 텍스트 셀을 클릭만으로 클립보드에 복사할 수 있는 기능을 확장했습니다. v1.5.10에서 공통 `CopyableTextCell` 몰리큘을 추출하고 채널 발행 테이블 제목/키워드에 적용했으며, v1.5.11에서 키워드 플래닝 테이블 키워드/주제까지, v1.5.17에서 병원 상세 계정 비밀번호로 확대되었습니다. v1.5.18에서는 URL 복사 버튼이 별도로 추가되었습니다.

### 사용 방법

1. 클릭 가능한 셀(제목/키워드/주제/비밀번호 등)에 마우스를 올리면 커서가 변경됨
2. 셀 클릭 시 클립보드에 텍스트가 복사되고 토스트로 알림
3. URL은 별도 복사 버튼으로 클립보드 저장

### 예제

채널 발행 보고서에서 제목 셀을 클릭하면 곧바로 "복사되었습니다" 토스트와 함께 클립보드에 저장됩니다. 병원 계정 비밀번호도 가시 처리된 상태에서 클릭 복사로 빠르게 가져올 수 있습니다.

## <span id="작가팀-담당-병원-관리">📋 작가팀 담당 병원 관리</span>

### 설명

작가팀 멤버가 기획·글작업을 분담할 수 있도록 담당 병원 관리 기능을 추가했습니다. v1.5.21에서 마이페이지에 기획 담당 병원 선택기를 도입하고, v1.5.23에서 writing 담당 추가 및 users/content-channels API 라우트가 통합되었으며, v1.5.24에서 by-type 통합 조회로 네트워크 호출이 절감되었습니다. v1.5.25에서는 키워드 기획 페이지에 글작업 담당 필터가 추가되어 본인 담당 분만 빠르게 확인할 수 있습니다.

### 사용 방법

1. 마이페이지 진입 (작가팀 멤버 한정)
2. "기획 담당 병원 선택" / "글작업 담당 병원 선택" 패널에서 병원 토글
3. 저장 후 키워드 기획 페이지의 글작업 담당 필터에서 본인 담당 분만 표시 가능

### 예제

작가가 마이페이지에서 본인의 기획·글작업 담당 병원을 각각 등록하면, 키워드 기획 페이지에서 해당 담당으로 필터링해 본인이 처리해야 할 항목만 볼 수 있습니다. 팀장은 팀원의 담당 병원도 확인 가능합니다.

## <span id="병원-컨펌-추가">📋 3차 컨펌 (병원 컨펌) 추가</span>

### 설명

채널 발행 컨펌 단계에 3차 컨펌(병원 컨펌) 컬럼이 추가되었습니다. v1.5.14에서 드롭다운 컬럼이 신설되었고, v1.5.16에서 컬럼 헤더가 '병원 컨펌'으로 명칭이 정리되었습니다. 기존 1차/2차 컨펌과 동일한 방식으로 상태를 변경할 수 있습니다.

### 사용 방법

1. 채널 발행 페이지에서 행의 '병원 컨펌' 컬럼 확인
2. 드롭다운에서 상태 선택 (예: 대기/확인/반려)
3. 저장 시 즉시 반영

### 예제

원고 1차/2차 컨펌이 완료된 뒤, 병원 측 최종 확인을 '병원 컨펌' 컬럼에 기록하여 발행 전 최종 게이트 역할을 합니다.

## <span id="키워드-기획-상태-인라인-편집">📋 키워드 기획 상태 인라인 편집</span>

### 설명

키워드 기획 테이블의 상태(status) 셀을 클릭만으로 바로 변경할 수 있도록 했습니다(v1.5.27). 별도의 수정 모드 진입 없이 셀 안에서 드롭다운이 열려 상태가 즉시 저장됩니다.

### 사용 방법

1. 키워드 기획 테이블에서 상태 셀 클릭
2. 드롭다운에서 상태 선택
3. 선택 즉시 서버에 반영, 목록 자동 갱신

### 예제

기존에는 행을 수정 모드로 진입한 뒤 상태를 바꿔 저장해야 했지만, 이제는 상태 셀 클릭 → 드롭다운 선택 한 번으로 끝납니다.

## <span id="디자인-시스템-리빌드">📋 디자인 시스템 리빌드</span>

### 설명

전체 디자인 시스템을 stone 뉴트럴 기반으로 재구축했습니다. 시안(secondary) 색상을 stone으로 교체하고, glass 효과의 불투명도와 blur를 정제하여 가독성을 높였습니다. 다크모드 누락을 전수 수정하고, accent 토큰(#E8590C)을 추가했습니다. AI slop 패턴(과도한 그라데이션, 컬러드 shadow, shimmer 등)을 일괄 정리했습니다.

### 사용 방법

1. 기존과 동일하게 사용합니다.
2. 다크모드 전환 시 모든 컴포넌트에서 일관된 스타일이 적용됩니다.
3. Pretendard 폰트가 기본 적용되어 텍스트 렌더링이 개선됩니다.

### 예제

사이드바, 헤더, 모달, 테이블 등 전 영역에서 stone 톤 기반의 정제된 UI가 표시되며, 다크모드에서도 동일한 품질을 유지합니다.

## <span id="병원-메모-기능">📋 병원 메모 기능</span>

### 설명

병원별 메모를 등록·조회·수정·삭제할 수 있는 기능을 추가했습니다. 병원 상세 기본정보 탭에 메모 섹션이 추가되었고, 카테고리별 아코디언으로 분류됩니다. 별도의 전체 메모 리스트 페이지(/hospital/memo)에서 모든 병원의 메모를 한눈에 확인할 수 있습니다.

### 사용 방법

1. 병원 상세 → 기본정보 탭에서 메모를 확인·등록합니다.
2. 사이드바 → 병원 관리 → 병원 메모에서 전체 리스트를 조회합니다.
3. 각 병원 카드 헤더의 등록 버튼으로 새 메모를 추가합니다.

### 예제

병원 상세 페이지에서 "진료 안내 변경" 메모를 등록하면 카테고리별 아코디언에 분류되어 표시되고, 전체 리스트 페이지에서도 해당 병원 그룹 아래에 표시됩니다.

## <span id="컨펌-시스템">📋 컨펌 시스템</span>

### 설명

채널 발행 포스트에 1차/2차 컨펌 워크플로우를 추가했습니다. 원고 보기/편집 모달(tiptap 기반 위지윅 에디터)을 통해 원고를 확인하고 컨펌 상태를 관리할 수 있습니다. 인라인 폼에 confirmUrl, 원고 입력 필드가 추가되었습니다.

### 사용 방법

1. 채널 발행 테이블에서 상태/원고 컬럼을 확인합니다.
2. 원고 보기 버튼으로 모달에서 원고를 확인·편집합니다.
3. 1차/2차 컨펌 버튼으로 단계별 승인을 진행합니다.

### 예제

작가가 원고를 작성하면 팀장이 1차 컨펌 후 최종 2차 컨펌을 진행하여 발행 상태로 전환됩니다.

## <span id="공용-toast-알림">📋 공용 Toast 알림</span>

### 설명

Zustand store 기반의 공용 Toast 알림 컴포넌트를 추가했습니다. default/success/error 3가지 variant를 지원하며, Framer Motion 애니메이션으로 우측 하단에서 슬라이드 인/아웃됩니다. 3초 후 자동 소멸되며, 여러 토스트가 스택으로 표시됩니다.

### 사용 방법

1. `useToast` 훅을 import합니다.
2. `const toast = useToast()`로 인스턴스를 가져옵니다.
3. `toast('메시지')` 또는 `toast({ message: '메시지', variant: 'success' })`로 호출합니다.

### 예제

키워드를 클릭하면 클립보드에 복사되고, 우측 하단에 "복사되었습니다" 토스트가 3초간 표시됩니다.

## <span id="키워드-클릭-복사-및-복사-개선">📋 키워드 클릭 복사 및 복사 개선</span>

2. 클립보드에 키워드가 복사되고 토스트로 확인됩니다.
3. 키워드 기획 페이지의 복사하기 버튼은 메모 없이 복사됩니다.

키워드 "형인재 데이터 칼럼"을 클릭하면 해당 텍스트가 클립보드에 복사되고 "복사되었습니다" 토스트가 표시됩니다.

## <span id="마케팅팀-채널-발행-보고-페이지">📋 마케팅팀 채널 발행 보고 페이지</span>

### 설명

마케팅팀 부서별 채널 10종(네이버 블로그, 지식iN, 하이닥, 뉴스 기사, 카페 글, 카페 댓글, 체험단, 인스타 카드뉴스, 인스타 릴스, 당근)의 발행 데이터를 병원별로 조회하고 추가·수정·삭제할 수 있는 전용 페이지입니다. 각 병원의 패키지 목표 수량 대비 실적을 한눈에 확인할 수 있으며, 부족한 발행 건수만큼 빈 입력행이 자동 생성됩니다. 마케터 필터, 검색, 연월 선택, 무한스크롤을 지원합니다.

### 사용 방법

1. 사이드바에서 마케팅팀 → 해당 부서를 클릭합니다.
2. 병원별 채널 발행 현황이 목표/실적과 함께 표시됩니다.
3. 빈 입력행에 URL, 제목 등을 입력하고 저장합니다.
4. 수정 버튼 클릭 시 해당 행이 인라인 편집으로 전환됩니다.
5. 삭제 버튼은 마케팅팀원에게만 표시되며, 확인 모달 후 삭제됩니다.
6. 복사하기 버튼으로 병원별 발행 데이터를 채널별로 분리하여 클립보드에 복사합니다.

### 예제

지식iN 2/4인 병원에서 빈 입력행 2개가 자동 생성되고, 기획 아이템의 키워드가 미리 채워져 있습니다. URL과 제목을 입력하고 저장하면 실적이 3/4로 갱신됩니다.

## <span id="사이드바-마케팅팀-동적-메뉴">📋 사이드바 마케팅팀 동적 메뉴</span>

### 설명

부서 API에서 이름에 "마케팅"이 포함된 부서를 자동으로 사이드바 메뉴에 추가합니다. 부서가 추가/삭제되면 메뉴도 자동 반영됩니다. 기존에 정적으로 관리되던 사이드바 경로 매칭 로직을 동적 메뉴에 대응하도록 개선하여 활성화 상태 표시 버그도 수정했습니다.

### 사용 방법

1. 관리자 페이지에서 "마케팅"이 포함된 부서를 추가합니다.
2. 사이드바에 자동으로 마케팅팀 하위 메뉴가 생성됩니다.
3. 해당 메뉴를 클릭하면 올바르게 활성화 표시됩니다.

### 예제

"마케팅1팀", "마케팅2팀" 부서가 있으면 사이드바에 마케팅팀 대메뉴 아래 두 개의 서브메뉴가 표시됩니다.

## <span id="블로그-수집-트리거">📋 블로그 수집 트리거</span>

### 설명

네이버 블로그 발행 페이지의 각 병원 그룹 헤더에 수집 버튼을 추가했습니다. 클릭 시 백엔드의 blog-collection 큐에 수집 작업을 등록하며, 5초 쿨다운으로 연속 클릭을 방지합니다.

### 사용 방법

1. 네이버 블로그 페이지에서 병원 그룹 헤더의 수집 버튼을 클릭합니다.
2. 로딩 스피너가 표시된 후 5초간 비활성화됩니다.
3. 백엔드에서 비동기로 블로그 수집이 진행됩니다.

### 예제

수집 버튼 클릭 → 202 Accepted 응답 → 큐에 등록 → 백그라운드 수집 실행.

## <span id="채널별-복사-기능">📋 채널별 복사 기능</span>

### 설명

마케팅팀 채널 발행 페이지에서 병원별 복사하기 버튼을 클릭하면 채널별로 분리된 보고서가 클립보드에 복사됩니다. 구글 시트에 붙여넣기하면 서식이 적용된 테이블로 표시됩니다. 각 채널의 특성에 맞는 컬럼(키워드, 댓글, 미디어 등)이 자동 적용됩니다.

### 사용 방법

2. 구글 시트에 붙여넣기합니다.
3. 채널별로 분리된 보고서 테이블이 표시됩니다.

### 예제

복사 결과: 네이버 블로그 발행 보고(6/10) → 지식iN 발행 보고(2/4) → 당근 발행 보고(2/2) 순서로 각각 헤더와 데이터가 포함됩니다.

## <span id="불필요-api-호출-정리-및-코드-품질-개선">📋 불필요 API 호출 정리 및 코드 품질 개선</span>

### 설명

ReactQuery의 글로벌 staleTime을 0에서 30초로 변경하여 불필요한 리페치를 줄였습니다. useDepartments 훅을 읽기전용(useDepartmentList)으로 분리하여 7개 파일에서 불필요한 mutation 객체 생성을 제거했습니다. useContentChannelsMutations의 setQueryData 3벌 낙관적 업데이트를 invalidateAll 1줄로 통합하여 780줄에서 215줄로 73% 감소시켰습니다.

### 사용 방법

1. 기존과 동일하게 사용합니다.
2. 키워드 기획/네이버 블로그 등에서 수정 시 불필요한 API 재호출이 줄어든 것을 확인할 수 있습니다.

### 예제

키워드 아이템 수정 후 기존에는 content-channels API가 3회 호출되었으나, 이제 invalidateQueries로 필요한 쿼리만 1회 리페치됩니다.

## <span id="키워드-아이템-삭제-및-확인-모달">📋 키워드 아이템 삭제 및 확인 모달</span>

키워드 오입력 항목을 선택해 삭제를 누르면 확인 모달이 먼저 열리고, 확인 시에만 실제 삭제가 수행됩니다.

## <span id="권한-정책-보강">📋 권한 정책 보강</span>

### 설명

작가 계정의 삭제 관련 권한을 보강하고, 키워드 삭제 기능에도 role 기반 조건을 반영했습니다. 이를 통해 사용자 역할에 맞는 액션만 허용되도록 경계를 명확히 했습니다. 운영 중 권한 혼선으로 발생하던 이슈를 줄이는 데 목적이 있습니다.

### 사용 방법

1. 권한이 다른 계정(예: 작가/관리자)으로 동일 화면에 접근합니다.
2. 삭제 가능 여부가 역할별로 다르게 노출되는지 확인합니다.
3. 허용된 역할에서만 삭제 액션이 정상 수행되는지 검증합니다.

### 예제

관리자 계정에서는 삭제 버튼이 활성화되지만, 비허용 역할 계정에서는 버튼이 비노출되거나 동작하지 않습니다.

## <span id="페이지-이동-및-상태관리-성능-개선">📋 페이지 이동 및 상태관리 성능 개선</span>

### 설명

페이지 이동 시 체감 성능을 높이기 위해 UI store 동작을 최적화하고 전환 흐름을 개선했습니다. 메뉴 전환 시 불필요한 지연이 줄어들어, 동일 작업을 반복할 때 화면 반응이 더 안정적으로 느껴집니다. 일상 운영 동선에서 누적되는 대기 시간을 줄이는 개선입니다.

### 사용 방법

1. 로그인 후 여러 메뉴를 연속으로 이동합니다.
2. 이전 대비 전환 시 끊김 또는 지연이 줄었는지 확인합니다.
3. 빈번히 사용하는 메뉴 구간에서 반응 속도를 비교합니다.

### 예제

관리자 설정과 키워드 기획 화면을 반복 이동해도 로딩 체감이 완화되어 작업 흐름이 부드럽게 유지됩니다.

## <span id="사이드바-반응형-동작-개선">📋 사이드바 반응형 동작 개선</span>

### 설명

작은 화면에서 작업할 때 본문 가독성을 확보할 수 있도록 사이드바 자동 축소를 적용했습니다. 뷰포트 크기에 맞춰 네비게이션이 더 유연하게 동작해, 좁은 해상도 환경에서도 핵심 콘텐츠 확인이 쉬워졌습니다.

### 사용 방법

1. 브라우저 너비를 줄여 작은 뷰포트 상태를 만듭니다.
2. 사이드바가 자동으로 축소되는지 확인합니다.
3. 다시 화면을 넓혀 기본 동작이 자연스럽게 복원되는지 확인합니다.

### 예제

노트북 절반 화면으로 ERP를 사용할 때 사이드바가 자동 축소되어 메인 테이블 영역을 더 넓게 사용할 수 있습니다.

## <span id="관리자-설정-기능-개선">📋 관리자 설정 기능 개선</span>

### 설명

관리자 화면에서 패키지/플랫폼 계정 타입 데이터 관리를 확장했습니다. 패키지 추가·삭제 기능을 보강하고, 패키지 0개 상태 예외를 정리했으며, 플랫폼 계정 타입도 추가/제거 가능하도록 반영했습니다. 운영 데이터의 정합성과 관리 편의성을 동시에 개선했습니다.

### 사용 방법

1. 관리자 설정 페이지에서 패키지 목록을 확인합니다.
2. 패키지를 추가/삭제하고 목록 반영 상태를 점검합니다.
3. 플랫폼 계정 타입을 추가/제거한 뒤 저장 결과를 확인합니다.

### 예제

불필요한 패키지를 제거한 뒤 즉시 목록에서 정리되고, 계정 타입 변경도 동일 화면에서 일관되게 관리할 수 있습니다.

## <span id="운영-편의-기능-개선">📋 운영 편의 기능 개선</span>

### 설명

운영 중 확인 빈도가 높은 영역에 테이블 로딩바를 추가해 상태 인지성을 높였습니다. 더불어 키워드 기획 날짜 처리와 당근 매크로 동작을 보정해 작업 정확도를 개선했습니다. 사용자 입장에서 "멈춘 것처럼 보이는 구간"을 줄이고 결과 예측 가능성을 높인 개선입니다.

### 사용 방법

1. 데이터가 많은 목록 화면을 열어 로딩 상태 표시를 확인합니다.
2. 키워드 기획 날짜 관련 동작을 실제 운영 시나리오로 점검합니다.
3. 당근 매크로 실행 후 결과 기록/반영 상태를 확인합니다.

### 예제

목록 조회 직후 로딩바가 표시되어 처리 진행 상태를 즉시 알 수 있고, 완료 후 데이터가 안정적으로 반영됩니다.
